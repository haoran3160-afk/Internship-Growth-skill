# 隐私边界

## 目标

在每次输出时判断内容能否进入目标位置，不要求用户搭建双 Vault、审批流或长期治理系统。

## 先判断目标位置

| 位置 | 可写内容 |
|---|---|
| 公司批准的位置 | 按公司政策允许的内部路径、术语、代码摘录和工作证据 |
| 个人 Obsidian | 脱敏事实、通用原理、独立重写示例和真实但不可识别的贡献描述 |
| 公开渠道 | 仅公开来源或明确获准公开的内容 |

当前对话也是目标位置。只有用户明确确认当前环境获准处理并显示相应内部内容时，才按“公司批准的位置”输出精确路径、源码或内部标识；否则默认按“个人 Obsidian”的脱敏边界回答。无需因此停止整个任务：先交付不含可识别来源的解释，并说明精确证据需要在获准位置查看。

非公开仓库和内部文档默认不是个人可导出的素材。公司政策和明确授权优先于本 Skill。

## `confidentiality` 取值

模板只使用以下四个值；它们是内容边界标签，不是审批流：

| 值 | 含义与允许动作 |
|---|---|
| `review-required` | 初始状态；目标位置、授权或脱敏尚未确认，不同步到个人库或公开渠道 |
| `company-internal` | 只保存在公司批准的位置，按公司政策保留必要内部证据 |
| `personal-sanitized` | 已完成个人内容检查，可进入个人 Obsidian，但仍不等于可公开 |
| `public` | 内容来自公开来源或已获明确公开许可，可对外分享 |

只有在目标位置和内容都满足对应条件后才更改标签。工具扫描、改名或删除少量字段不能把内容自动升级为 `personal-sanitized` 或 `public`。

## 个人内容检查

个人版本不得包含：

- 密钥、凭据、个人数据、客户数据或安全敏感信息。
- 非公开源码、schema、内部路径、主机名、工单、架构图或接口标识。
- 公司、客户、代号、未发布功能、事故或漏洞的可识别细节。
- 非公开规模、成本、收入、性能、可靠性或安全指标。
- 通过改名仍能还原来源的实现、截图或映射关系。

个人理解笔记中的 `E1`、`E2` 等证据句柄只能连接本笔记内的脱敏结论，不得编码仓库、路径、commit 或工单，也不得建立可逆对照表。

## 安全转化

1. 从来源中提取通用问题、不变量和取舍。
2. 移开来源。
3. 使用不同领域、数据形状和结构独立设计示例。
4. 为新示例编写自己的验证。
5. 只在概念层检查是否表达完整。

如果仍能识别原项目，或者授权不清楚，就停止个人写入；可以在对话中说明需要确认的政策问题。工具扫描不能替代人工判断，也不能授予导出许可。

## 完成标准

- 目标位置已经明确。
- `confidentiality` 使用已定义值，且与目标位置和授权一致。
- 输出内容符合该位置的允许范围。
- 个人示例是独立创作而非改名副本。
- 不确定内容保持在公司批准的位置或不写入。
